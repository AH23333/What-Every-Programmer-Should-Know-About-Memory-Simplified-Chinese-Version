# 第 1 章 引言

早期的计算机相对简单，系统中的各个组件，如 CPU、内存、大容量存储设备 (mass storage) 及网络接口 (network interface)，在相近时间发展，因此在性能表现相对平衡。
以数据访问为例，内存和网络接口的速度尽管不若 CPU 快，但差异不显著。

随着计算机基础结构的稳定及硬件开发者专注于优化独立的子系统，这种情况发生变化：一些计算机组件的性能突然大幅落后，成为系统的瓶颈。
尤其是大容量存储设备和内存，由于成本的限制，与其他系统相比，改进相对缓慢。

大容量存储设备的性能问题主要借助软件技术解决：操作系统 (operating system) 将最常使用 (且最有可能使用) 的数据保存在主存 (main memory) 中，
其访问速度比硬盘 (hard disk) 快了几个数量级。
此外，缓存也加到存储设备中，以提升性能，这不需要对操作系统进行任何改变[^1]。
由于偏离本文的主旨，我们不会深入探讨有关大型存储设备访问的软件优化细节。

相较于存储子系统，解决主存的瓶颈被证实更加困难，因为几乎所有的解决方法都需要改变硬件。
目前有以下主要方式来改善主存的性能：

* RAM 的硬件设计，包括速度和并行度 (parallelism) 的提升
* 内存控制器 (controller) 的设计改进
* CPU 缓存的运用
* 设备的直接内存访问 (Direct Memory Access，简称 DMA)

本文主要涉及 CPU 缓存和内存控制器设计对系统性能的影响，探索这些主题的过程中，我们将深入了解直接内存访问 (DMA)。
不过，我们首先需要从现今商用硬件的设计概览开始，这是理解如何高效使用内存子系统以及其限制的必要条件。
同时，我们也提及不同类型的 RAM，以及为何这些差异仍然存在。

值得一提的是，本文件并非最终且完整的版本，仅涵盖商用硬件的一个子集，且许多主题的讨论仅止于基本概念。
对于这些主题，建议读者参照更详尽的文件。

提及特定操作系统的细节和解决方法时，本文仅针对 Linux，不会包含其他操作系统的任何信息，作者无意详述其他操作系统。
若读者觉得需要使用不同的操作系统，建议参照相应供应商所提供的文件。

最后，本文中多处使用“通常”和类似修饰词，讨论的技术在现实世界中存在许多不同的变体，本文仅针对最常见且主流的版本进行讨论。
因此，这些技术往往没有绝对的答案或解决方案。

## 文件结构

本文主要针对软件开发者编写，不细究对于硬件方向读者有用的硬件技术细节。
然而，谈及能为开发者提供实用信息之前，有一些基础知识是必要的。

为了达到这个目标，第二节将以技术细节介绍随机访问内存 (Random-Access Memory，简称 RAM)，这一节的内容值得一读，但对于后面几节的理解并非必要。
在需要这节内容的地方，我们会提供相应的引用 (back reference)，所以急于掌握主题的读者可暂时略过本节的大部分内容。

第三节描述多项 CPU 缓存行为的细节。为了避免冗长的文字，我们将使用一些图表来说明。
这一节的内容对于理解后续章节是必不可少的。
第四节简要介绍虚拟内存 (virtual memory) 的实现方式，这也是后续内容的基础。

第五节则详细论述了非均匀内存访问 (Non-Uniform Memory Access，简称 NUMA) 系统的细节。

第六节是本文的关键章节，将整合前几节的知识，并向程序员提供如何在不同情境下编写高效程序的建议。
对于非常急切的读者，可从这一节开始，并在需要时回顾前几节的基础知识。

第七节介绍一些能够帮助程序员提升性能的工具。
即使完全理解这些技术，解决复杂软件项目的问题仍然远远不够，因此某些工具是必要的。

最后，在第八节中，我们将展望未来几年中可期待或希望拥有的技术发展。
